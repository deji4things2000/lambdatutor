# Lambda Tutor

An interactive lambda-calculus tutor implemented from the specification in
`spec.tex`. Evaluation and type checking run locally and deterministically;
Dartmouth receives structured traces only when an explanation is requested.

## What is implemented?

### Untyped lambda calculus

- Lambda notation with named variables
- Application and beta reduction
- `lazy` and `full` evaluation strategies
- Structured JSON reduction traces
- Dartmouth explanations grounded in the trace
- Offline reduction explanations when no Dartmouth key is configured

### Typed lambda calculus (STLC)

The current implementation includes the core typed-tutor feature requested in
the lecture feedback:

- Base types `Int`, `Bool`, and `Unit`
- Function types such as `Int -> Int`
- Typed lambda parameters, for example `\x:Int. x`
- Integer and boolean literals
- `if` expressions
- Application type checking and unification
- Structured diagnostics for unbound variables, mismatches, non-functions,
  infinite types, and terms whose type cannot be inferred
- Suggested corrections generated by the local checker

Use `:type EXPR` to inspect a type or diagnostic, and `:typed` to require a
successful type check before evaluating an expression. The local checker is
authoritative: the LLM explains reduction traces, but does not decide types or
invent corrections. Full typing-derivation explanations through Dartmouth are
not yet wired into the REPL.

## Requirements

- Python 3.10 or newer
- No third-party Python packages are required for offline use
- `certifi` is recommended for live Dartmouth calls when Python cannot find a
  trusted CA bundle
- A Dartmouth API key is optional. Without one, reduction explanations use a
  local deterministic fallback.

Check the Python version before running:

```bash
python3 --version
```

If `python3` is older than 3.10, use an explicit newer interpreter in the
commands below, for example `python3.10`.

## Quick start: offline mode

From a fresh checkout:

```bash
cd /Users/user_1/lambdatutor
python3.10 --version
make test
python3.10 lambda_tutor.py
```

Try this at the `λ>` prompt:

```text
(\x. x) 4
:trace
:explain
:type \x:Int. x
:quit
```

Offline mode evaluates and type-checks locally. `:explain` uses a local
deterministic explanation because no Dartmouth key is configured.

## Run the tutor

From the repository root:

```bash
python3.10 lambda_tutor.py
```

Or, if `python3` points to Python 3.10 or newer:

```bash
make repl
```

The REPL accepts ordinary lambda expressions and these commands:

| Command | Description |
| --- | --- |
| `:type EXPR` | Infer and print the STLC type or a structured error |
| `:trace` | Print the most recent reduction trace as JSON |
| `:explain` | Explain the most recent trace |
| `:follow-up QUESTION` | Ask a question about the most recent trace |
| `:mode lazy` / `:mode full` | Select the reduction strategy |
| `:typed` | Toggle type checking before evaluation |
| `:models` | Refresh and interactively select a Dartmouth model |
| `:help` | Print the command list |
| `:quit` | Exit |

Example session:

```text
λ> (\x. x) 4
=> 4 (1 steps)
λ> :trace
{
  "kind": "reduction",
  ...
}
λ> :explain
0. Apply (λx. x) to 4 to get 4.
The computation ends at 4.
λ> :type \x:Int. x
Int -> Int
λ> :quit
```

In a shell, quote expressions containing backslashes:

```bash
printf ':type \\x:Int. x\n(\\x. x) 4\n:trace\n:explain\n:quit\n' \
  | python3.10 lambda_tutor.py
```

## Run the tests

The test suite uses Python's standard-library `unittest`:

```bash
python3.10 -m unittest discover -s tests -v
```

Or:

```bash
make test
```

The current tests cover identity reduction, nested application, application
parsing, typed identity, rejection of an unannotated type that cannot be
inferred, model endpoint construction, model selection, and stale-model
reselection.

## Enable Dartmouth explanations

Create a local environment file from the checked-in template:

```bash
cp .env.example .env
```

Edit `.env` and set your key:

```dotenv
DARTMOUTH_CHAT_API_KEY=your-key
DARTMOUTH_CHAT_URL=https://chat.dartmouth.edu/api/chat/completions
# Leave empty to select interactively at startup.
DARTMOUTH_MODEL=
# Set this after installing certifi if your Python reports TLS errors.
DARTMOUTH_CA_BUNDLE=
```

Load the variables into the current shell before starting the REPL:

```bash
set -a
source .env
set +a
python3.10 lambda_tutor.py
```

On startup, the tutor calls Dartmouth's `/api/models` endpoint and displays
the models available to your account. Enter a number to select one. The choice
lasts for the current process. Use `:models` to refresh or switch models.
After selecting a model, run:

```text
(\x. x) 4
:explain
```

To persist a selected model, set its exact returned ID in `.env`, for example:

```dotenv
DARTMOUTH_MODEL=anthropic.claude-haiku-4-5-20251001
```

If that model later becomes unavailable, startup detects it and opens the
selector again.

The application reads these environment variables:

| Variable | Required | Purpose |
| --- | --- | --- |
| `DARTMOUTH_CHAT_API_KEY` | For live API calls | Dartmouth bearer credential |
| `DARTMOUTH_CHAT_URL` | No | Chat completions endpoint override |
| `DARTMOUTH_MODEL` | No | Model ID; empty enables interactive selection |
| `DARTMOUTH_CA_BUNDLE` | No | Path to a trusted PEM CA bundle |

The client uses the OpenAI-compatible Dartmouth endpoint:

```text
https://chat.dartmouth.edu/api/chat/completions
```

`.env` is ignored by Git, while `.env.example` is safe to commit. Do not put
real API keys, passwords, or other credentials in source files or commit
history. If `DARTMOUTH_CHAT_API_KEY` is not set, the tutor uses its offline
fallback for reduction explanations. If a live request fails, it reports the
error after retrying transient failures rather than pretending an API response
was received.

When `DARTMOUTH_CHAT_API_KEY` is set and `DARTMOUTH_MODEL` is empty, the REPL
fetches the models available to your account, displays them as a numbered list,
and asks you to choose one. The selection applies to the current process. Use
`:models` at any time to refresh the list and choose another model. To make a
selection persistent, copy its ID into `.env` after choosing. If `.env`
contains a model that Dartmouth no longer offers, startup detects that stale
value and opens the selector automatically.

### Fixing a certificate error

If startup reports `CERTIFICATE_VERIFY_FAILED`, Python cannot find a trusted
CA bundle on your machine. Do not disable TLS verification. If you installed
Python from python.org on macOS, run its certificate installer once:

```bash
/Applications/Python\ 3.10/Install\ Certificates.command
```

Then start a new shell and retry. If your organization provides a trusted PEM
CA bundle, set its path in `.env`:

```dotenv
DARTMOUTH_CA_BUNDLE=/absolute/path/to/your/ca-bundle.pem
```

For Anaconda or Miniconda, check whether the `certifi` CA bundle is available:

```bash
python3.10 -c "import certifi; print(certifi.where())"
```

If that import fails, install it into the same Python environment:

```bash
python3.10 -m pip install certifi
```

Then use the trusted bundle path reported by Python:

```bash
export DARTMOUTH_CA_BUNDLE="$(python3.10 -c 'import certifi; print(certifi.where())')"
python3.10 lambda_tutor.py
```

To make that setting persistent, write the printed path into `.env`:

```bash
python3.10 -c 'import certifi; print("DARTMOUTH_CA_BUNDLE=" + certifi.where())'
```

Reload `.env` and verify the file before starting the tutor:

```bash
set -a
source .env
set +a
test -f "$DARTMOUTH_CA_BUNDLE" && echo "CA bundle found"
```

You can also use an existing system variable:

```bash
export SSL_CERT_FILE=/absolute/path/to/your/ca-bundle.pem
```

The tutor keeps certificate verification enabled and will report a clear
error if the configured bundle is missing, invalid, or cannot validate
Dartmouth's certificate.

## Check that Dartmouth is running

Load your local credentials, then send a small non-streaming chat request:

```bash
set -a
source .env
set +a

curl --fail-with-body --silent --show-error \
  "$DARTMOUTH_CHAT_URL" \
  -H "Authorization: Bearer ${DARTMOUTH_CHAT_API_KEY}" \
  -H "Content-Type: application/json" \
  --data '{
    "model": "'"${DARTMOUTH_MODEL}"'",
    "messages": [
      {"role": "user", "content": "Reply with exactly: Dartmouth API is running"}
    ],
    "stream": false
  }'
```

For a successful request, the response should be JSON containing a
`choices[0].message.content` value with the model's reply. A failed request
will include an HTTP or API error; common causes are an unset or expired key,
an incorrect endpoint, or an unavailable model. To inspect only the HTTP
status without printing the response body:

```bash
curl -sS -o /dev/null -w 'HTTP %{http_code}\n' \
  "$DARTMOUTH_CHAT_URL" \
  -H "Authorization: Bearer ${DARTMOUTH_CHAT_API_KEY}" \
  -H "Content-Type: application/json" \
  --data '{"model":"'"${DARTMOUTH_MODEL}"'","messages":[{"role":"user","content":"ping"}],"stream":false}'
```

Do not include the API key in the command itself, screenshots, logs, or
commits. The commands above should use the loaded
`Authorization: Bearer ${DARTMOUTH_CHAT_API_KEY}` header.

### Terminal input note

The REPL reads plain text input. If an arrow key is pasted or sent as an
escape sequence, it may appear as `^[[C` and produce an unexpected-character
error. Press arrow keys normally in the terminal, or re-enter the expression
without the escape sequence:

```text
(\x. x) 4
```

If you see `{"detail":"Model not found"}`, your key and endpoint are working;
the model ID is unavailable or misspelled. List the models available to your
account:

```bash
curl --fail-with-body --silent --show-error \
  "https://chat.dartmouth.edu/api/models" \
  -H "Authorization: Bearer ${DARTMOUTH_CHAT_API_KEY}"
```

Choose an `id` from the returned `data` array, put it in `.env`, reload the
environment, and retry:

```bash
sed -i '' "s/^DARTMOUTH_MODEL=.*/DARTMOUTH_MODEL=the-id-you-chose/" .env
set -a
source .env
set +a
```

## Supported expression syntax

```text
(\x. x) 4
\x:Int. x
\x:Bool. if x 1 0
true
false
if true 1 0
```

Applications associate to the left. Parentheses can be used to control
grouping. Typed lambda parameters use `\name:Type. body`, where the supported
base types are `Int`, `Bool`, and `Unit`.
